15  Maximum Likelihood Estimation

EDIT THIS SECTION

Machine learning models make predictions from data that is inherently noisy, and are themselves trained using randomly-sampled batches of data (Section 18.4.1). Probability and statistics provide the language for reasoning rigorously about both of these sources of uncertainty. This section introduces the small set of concepts genuinely load-bearing for the rest of the unit: estimators and their bias/variance, and maximum likelihood estimation — which turns out to be the hidden justification for the loss functions already used, without derivation, in Chapter 16.

For generating and sampling from probability distributions numerically, see Chapter 12, which covers this in detail and is not repeated here.

15.1 Estimators

An estimator is simply a function of observed data that produces a guess at some unknown quantity. For example, given \(N\) samples \(x_1, \ldots, x_N\) drawn from some distribution, the sample mean

\[ \hat{\mu} = \frac{1}{N}\sum_{i=1}^N x_i \]

is an estimator of the true (unknown) population mean \(\mu\).

Because the data is random, the estimator itself is a random variable — if you drew a different sample of \(N\) points, you’d get a different value of \(\hat{\mu}\). This means an estimator has its own distribution, and in particular its own mean and variance, which turn out to be exactly analogous to the bias–variance tradeoff already introduced for machine learning models in Section 16.9.

15.1.1 Bias

The bias of an estimator is the difference between its expected value and the true value it’s estimating:

\[ \text{Bias}(\hat{\theta}) = \mathbb{E}[\hat{\theta}] - \theta \]

An estimator is unbiased if this is zero — i.e. if, averaged over infinitely many repeated samples, it would recover the true value exactly.

15.1.2 Variance

The variance of an estimator measures how much it fluctuates from one sample to the next:

\[ \text{Var}(\hat{\theta}) = \mathbb{E}\left[(\hat{\theta} - \mathbb{E}[\hat\theta])^2\right] \]

import numpy as np
rng = np.random.default_rng(1)

true_mu = 5.0
N = 20
n_experiments = 5000

estimates = [rng.normal(true_mu, 2.0, size=N).mean() for _ in range(n_experiments)]

print(f"Mean of estimator across experiments : {np.mean(estimates):.3f}  (true value = {true_mu})")
print(f"Bias                                  : {np.mean(estimates) - true_mu:.4f}")
print(f"Variance of estimator                 : {np.var(estimates):.4f}")
Mean of estimator across experiments : 4.991  (true value = 5.0)
Bias                                  : -0.0092
Variance of estimator                 : 0.1928

The sample mean is unbiased and its variance shrinks as \(N\) grows — a direct, quantitative version of the intuition that “more data gives a more reliable estimate.”

15.1.3 The Bias–Variance Decomposition

It’s a standard (and important) result that the expected squared error of an estimator decomposes as:

\[ \mathbb{E}\left[(\hat\theta - \theta)^2\right] = \text{Bias}(\hat\theta)^2 + \text{Var}(\hat\theta) \]

This is worth comparing directly to the bias–variance tradeoff of Section 16.9: an underfit model is analogous to a high-bias estimator (systematically wrong, but consistent across different training sets), while an overfit model is analogous to a high-variance estimator (correct on average, but wildly sensitive to exactly which training data it saw). The two “bias–variance tradeoffs” you’ll meet in this unit — one for statistical estimators, one for ML models — are, in fact, the same tradeoff, since fitting a model is itself just estimating parameters from a finite random sample of data.

15.2 Likelihood

Given some observed data \(\mathcal{D}\) and a model with parameters \(\theta\), the likelihood is a function of \(\theta\) that says how probable the observed data would have been, under a given choice of parameters:

\[ \mathcal{L}(\theta) = P(\mathcal{D} \mid \theta) \]

Note carefully: the likelihood is a function of \(\theta\), with the data held fixed — this is the opposite of a probability distribution over the data, and is a common point of confusion.

For \(N\) independent data points, the likelihood factorises as a product:

\[ \mathcal{L}(\theta) = \prod_{i=1}^N P(x_i \mid \theta) \]

15.3 Maximum Likelihood Estimation

Maximum Likelihood Estimation (MLE) is the principle of choosing the parameters \(\theta\) that make the observed data as probable as possible:

\[ \hat{\theta}_{\text{MLE}} = \arg\max_\theta \mathcal{L}(\theta) \]

Because a product of many small probabilities is numerically awkward (it underflows very quickly), and because logarithms turn products into sums, it is standard practice to instead maximise the log-likelihood:

\[ \ell(\theta) = \log \mathcal{L}(\theta) = \sum_{i=1}^N \log P(x_i \mid \theta) \]

Since \(\log\) is monotonic, this doesn’t change the location of the maximum. And since we’ve been minimising things throughout ?sec-optimisation, it’s conventional to instead minimise the negative log-likelihood (NLL):

\[ \hat{\theta}_{\text{MLE}} = \arg\min_\theta \left[ -\sum_{i=1}^N \log P(x_i \mid \theta) \right] \]

This connects MLE directly to everything in ?sec-optimisation: fitting a model by MLE is just another instance of the minimisation problem already studied there, and can be solved using exactly the same gradient descent machinery (Chapter 18).

15.3.1 Worked example: fitting a Gaussian

Suppose we assume our data is drawn from a Gaussian with unknown mean \(\mu\) and known variance \(\sigma^2\). The log-likelihood is:

\[ \ell(\mu) = -\frac{1}{2\sigma^2}\sum_{i=1}^N (x_i - \mu)^2 + \text{const.} \]

Maximising this with respect to \(\mu\) (by setting the derivative to zero — a one-line application of Chapter 19) gives \(\hat\mu = \frac{1}{N}\sum x_i\): the maximum likelihood estimate of a Gaussian’s mean is exactly the sample mean used as our running example above.

import scipy.optimize as opt

data = rng.normal(loc=7.0, scale=2.0, size=200)

def negative_log_likelihood(mu):
    sigma = 2.0  # assumed known
    return -np.sum(-0.5*np.log(2*np.pi*sigma**2) - (data - mu)**2 / (2*sigma**2))

result = opt.minimize_scalar(negative_log_likelihood)
print(f"MLE estimate of mu : {result.x:.3f}")
print(f"Sample mean         : {data.mean():.3f}")
MLE estimate of mu : 7.206
Sample mean         : 7.206

As expected, numerically minimising the negative log-likelihood recovers the sample mean.

15.4 MLE Is the Hidden Justification for Your Loss Functions

This is the key payoff of this section, and it directly explains material presented without derivation in Chapter 16.

Mean Squared Error is MLE under a Gaussian noise assumption. If we assume that observed targets are the model’s prediction plus Gaussian noise, \(y_i = f(x_i) + \varepsilon_i\) with \(\varepsilon_i \sim \mathcal{N}(0, \sigma^2)\), then (following exactly the derivation above) the negative log-likelihood is, up to an additive and a multiplicative constant that don’t affect the location of the minimum:

\[ -\ell(\theta) = \frac{1}{2\sigma^2}\sum_{i=1}^N (y_i - f(x_i))^2 + \text{const.} \]

which is minimised by exactly the same \(\theta\) as the Mean Squared Error loss already defined in Chapter 16. In other words: using MSE as a loss function is implicitly assuming Gaussian-distributed errors, whether or not that assumption is stated explicitly.

Binary Cross-Entropy is MLE under a Bernoulli assumption. If each label \(y_i \in \{0, 1\}\) is modelled as a Bernoulli random variable with success probability \(\hat{P}_i\) (the model’s predicted probability), the likelihood of one observation is \(\hat{P}_i^{y_i}(1-\hat{P}_i)^{1-y_i}\), and the negative log-likelihood over \(N\) points is:

\[ -\ell(\theta) = -\sum_{i=1}^N \Big[ y_i \log \hat{P}_i + (1-y_i)\log(1-\hat{P}_i) \Big] \]

which is, term for term, exactly the Binary Cross-Entropy loss already given in Chapter 16. That loss function was not an arbitrary design choice — it is precisely the MLE objective for a binary classification model.

This is a genuinely useful piece of insight for a physicist: it means that choosing a loss function is equivalent to making an assumption about the noise model generating your data, and the “right” loss function for a given problem is the one implied by however you believe your measurement errors are actually distributed.
